JMM(Java Memory Model) Java 内存模型。Java层面抽象出来的概念，定义了主存、工作内存。

JMM 体现在如下几个方面：

  • 原子性（保证指令不会受到线程上下文切换的影响）
  • 可见性（保证指令不会受cpu缓存的影响）
  • 有序性（保证指令不会受cpu指令并优化的影响）

Java 内存模型的样子如下图。

工作方式，所有的共享变量都在主存中进行存储，然后每个线程都有自己的工作内存。它们在运行的时候从主存中读取变量到自己的工作内存中，然后对这个变量进行修改，修改之后在刷回去主存。

三个特性

可见性

可见性问题

导致可见性问题的原因

解决办法

  • 使用volatile（注意：volatile只是解决可见性，没有解决原子性）
  • 使用synchronized

当一个线程修改了主存中的共享数据以后，其他的线程可以及时的发现，使用volatile关键字即可。

volatile 适合用在一个线程写，其余的线程都是读的情况下。

有序性

JVM会在不影响结果的正确性的前提下会做指令的重排序，这样就会导致代码的执行顺序不一样，CPU层面并行执行，为了提升执行的效率，串行执行的时候会并行执行多条指令，提升执行效率。

Java的JIT编译器可能会进行指令的重排序，导致三种结果的出现 1 ，4，0，如果不想要指令的重排序，直接使用volatile关键字即可。

原子性

在程序代码执行的时候，各个线程之间独立的去运行，不会相互的干扰。

Volatile 原理

Volatile保证可见和有序性但是保障不了原子，Volatile底层原理实现是内存屏障机制 Memory Barrier（Memory Fence）

针对volatile变量的写指令后面会加入写屏障，不会将写屏障之前的代码排在写屏障之后。

针对volatile变量的读指令前面会加入读屏障，不会将读屏障之后的代码排在读屏障之前。

双重检查锁（Double-Checked-Locking）

双重检查锁没有添加volatile产生的问题

字节码信息

  • t1线程开始创建Singleton这个实例
  • t1线程复制一遍自己的引用
  • t1线程开始给INSTANCE实例赋值，此时初始化方法还并未完成
  • t2线程开始获取INSTANCE引用
  • t2判断INSTANCE对象是否为空，发现不为空，return返回，开始使用INSTANCE对象，此时INSTANCE线程并未完成初始化，拿到的是一个半成品
  • t1线程完成构造方法。

解决办法就是加上volatile

Happens-before规则

happens-before规定了对共享变量的写操作对其他线程的读操作可见，是一套可见性和有序性的一套规则的总结。

规则一

线程解锁m之前对变量的写，对于接下来对m加锁的其他线程对该变量的读可见。

一个线程在放开 m 锁之前改过的变量，别的线程之后只要再拿到 m 这把锁，就一定能看到这些改动。

规则二

线程对volatile变量的写，对接下来其他线程对该变量的读可见。

规则三

线程start前对变量的写，对该线程开始后对该变量的读可见。

在线程启动之前改好的变量，等这个线程跑起来以后，读到的就是改后的值。

规则四

线程结束前对变量的写，对其他线程得知它结束后的读可见（比如其他线程调用t1.isAlive 或 t1.join）等。

规则五

线程t1打断t2（interrupt）前对变量的写，对于其他线程得知t2被打断后对变量的读可见，（通过t2.interrupted 或者 t2.isInterrupted）

线程干完活再退出，它退出前写的东西，别人等它结束后都能看见

规则六

针对变量默认值（0，false，null）的写，对其他线程对该变量的读可见。

规则七

具有传递性，如果x hb -> y 并且 y hb -> z 那么有 hb -> z，配合volatile的指令重排。

t1线程里面做赋值动作，t2线程里面做读取，volatile变量赋值之前的变量对t2线程过可见
